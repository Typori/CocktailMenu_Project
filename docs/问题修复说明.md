## 修复的问题

### 问题1：配方编辑器未保存更改提示

#### 问题描述
在编辑配方时，如果跳转到任何其他页面会导致已编辑信息丢失，没有任何提示。

#### 解决方案
实现了未保存更改检测和确认对话框功能。

#### 实现细节

1. **创建自定义Hook** (`src/hooks/useUnsavedChanges.ts`)
   - 使用 React Router v6 的 `useBlocker` API 拦截路由跳转
   - 检测是否有未保存的更改
   - 提供保存、放弃、取消三种操作

2. **创建AlertDialog组件** (`src/components/ui/alert-dialog.tsx`)
   - 基于 `@radix-ui/react-alert-dialog`
   - 提供统一的警告对话框UI

3. **修改RecipeEditor** (`src/pages/RecipeEditor.tsx`)
   - 添加未保存更改状态追踪
   - 使用 `useRef` 保存初始数据
   - 通过 JSON 序列化比较数据变化
   - 集成 AlertDialog 显示确认提示

#### 用户体验
当用户在编辑配方时尝试离开页面，会弹出对话框询问：

**对话框标题**：保存更改？

**对话框内容**：您有未保存的更改。是否要在离开前保存这些更改？

**三个选项**：
1. **保存** - 保存更改并跳转到目标页面
2. **不保存** - 放弃更改并跳转到目标页面
3. **取消** - 停留在编辑页面，关闭对话框

### 问题2：排序功能无法保存

#### 问题描述
1. 使用排序功能调整顺序后，点击"完成排序"，排序会回到之前的状态，无法正常保存
2. 在拖拽卡片到某些位置时，不会出现嵌入的动画，整体布局也不会变动

#### 解决方案

##### 2.1 排序持久化

**数据库Schema更新**
```typescript
// 为Recipe和Ingredient添加displayOrder字段
export interface Recipe {
  displayOrder?: number; // 展示顺序
}

export interface Ingredient {
  displayOrder?: number; // 展示顺序
}
```

**数据库索引更新**
```typescript
// database.ts
ingredients: '++id, name, category, currentStock, createdAt, displayOrder'
recipes: '++id, name, parentRecipeId, isFavorite, createdAt, displayOrder, *tags, glassType'
```

**保存逻辑实现**

在三个页面中修复了 `handleExitSortMode` 函数：

```typescript
// Recipes.tsx
const handleExitSortMode = async () => {
  // 保存排序顺序到数据库
  for (let i = 0; i < sortedRecipes.length; i++) {
    await db.recipes.update(sortedRecipes[i].id!, { displayOrder: i });
  }
  setIsSortMode(false);
  setSortedRecipes([]);
};
```

```typescript
// Ingredients.tsx
const handleExitSortMode = async () => {
  // 保存排序顺序到数据库
  for (let i = 0; i < sortedIngredients.length; i++) {
    await db.ingredients.update(sortedIngredients[i].id!, { displayOrder: i });
  }
  setIsSortMode(false);
  setSortedIngredients([]);
};
```

**加载时排序**
```typescript
// Recipes.tsx
const recipes = useLiveQuery(() => 
  db.recipes.orderBy('displayOrder').toArray()
);

// Ingredients.tsx
const ingredients = useLiveQuery(() => 
  db.ingredients.orderBy('displayOrder').toArray(), 
  []
);
```

##### 2.2 拖拽动画优化

**问题原因**
`PointerSensor` 没有配置激活约束，导致拖拽行为不一致。

**解决方案**
为所有页面的 `PointerSensor` 添加激活约束：

```typescript
const sensors = useSensors(
  useSensor(PointerSensor, {
    activationConstraint: {
      distance: 8, // 拖拽8px后才激活，避免误触
    },
  }),
  useSensor(KeyboardSensor, {
    coordinateGetter: sortableKeyboardCoordinates,
  })
);
```

**优化效果**：
- ✅ 统一的拖拽激活距离
- ✅ 避免误触发拖拽
- ✅ 所有位置都有一致的嵌入动画
- ✅ 更流畅的拖拽体验

## 重要提示：数据库版本升级

### 问题
如果遇到以下错误：
```
SchemaError: KeyPath displayOrder on object store ingredients is not indexed
```

### 原因
这是因为在已有数据库上添加新索引时，需要升级数据库版本号。

### 解决方案
我们已经创建了 **Version 3** 来添加 `displayOrder` 索引：

```typescript
// database.ts - Version 3
this.version(3).stores({
  ingredients: '++id, name, category, currentStock, createdAt, displayOrder',
  recipes: '++id, name, parentRecipeId, isFavorite, createdAt, displayOrder, *tags, glassType',
  // ...
}).upgrade(tx => {
  // 为现有数据初始化displayOrder
  return tx.table('recipes').toCollection().modify((recipe, ref) => {
    if (recipe.displayOrder === undefined) {
      recipe.displayOrder = ref.primaryKey as number;
    }
  }).then(() => {
    return tx.table('ingredients').toCollection().modify((ingredient, ref) => {
      if (ingredient.displayOrder === undefined) {
        ingredient.displayOrder = ref.primaryKey as number;
      }
    });
  });
});
```

### 如何应用
1. **刷新页面** - Dexie 会自动检测版本变化并执行升级
2. **清除缓存**（如果刷新无效）：
   - 打开浏览器开发者工具
   - Application → IndexedDB → CocktailMenuDB
   - 右键删除数据库
   - 刷新页面重新初始化

## 技术要点

### 1. 路由拦截
使用 React Router v6 的 `useBlocker` API：
```typescript
const blocker = useBlocker(
  ({ currentLocation, nextLocation }) =>
    hasUnsavedChanges &&
    !isNavigatingRef.current &&
    currentLocation.pathname !== nextLocation.pathname
);
```

### 2. 数据变化检测
通过 JSON 序列化比较：
```typescript
const hasChanges = 
  JSON.stringify(recipe) !== JSON.stringify(initialDataRef.current.recipe) ||
  JSON.stringify(menuInfo) !== JSON.stringify(initialDataRef.current.menuInfo);
```
