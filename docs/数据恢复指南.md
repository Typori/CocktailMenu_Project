# 数据恢复指南

## 问题：页面显示没有数据

如果您在升级后发现原料和配方页面显示为空，**不要担心，数据还在**！这是查询问题，不是数据丢失。

---

## 快速修复步骤

### 方法1：使用调试工具（推荐）

1. **打开浏览器控制台**
   - 按 `F12` 或 `Ctrl+Shift+I` (Windows/Linux)
   - 按 `Cmd+Option+I` (Mac)

2. **在控制台中运行以下命令**
   ```javascript
   // 检查数据库状态
   await dbDebug.checkStatus()
   ```
   
   您应该能看到数据数量，例如：
   ```
   配方数量: 10
   原料数量: 25
   ```

3. **如果看到数据，运行修复命令**
   ```javascript
   // 修复displayOrder字段
   await dbDebug.fixDisplayOrder()
   ```

4. **刷新页面**
   - 按 `F5` 或 `Ctrl+R`
   - 数据应该恢复显示了

### 方法2：手动刷新页面

1. **硬刷新浏览器**
   - Windows/Linux: `Ctrl+Shift+R`
   - Mac: `Cmd+Shift+R`

2. **清除浏览器缓存**
   - 打开开发者工具 (F12)
   - 右键点击刷新按钮
   - 选择"清空缓存并硬性重新加载"

### 方法3：检查IndexedDB

1. **打开开发者工具** (F12)

2. **进入Application标签**
   - 展开 **IndexedDB**
   - 展开 **CocktailMenuDB**

3. **检查数据表**
   - 点击 `recipes` 表 - 查看是否有配方数据
   - 点击 `ingredients` 表 - 查看是否有原料数据

4. **如果数据存在**
   - 说明只是显示问题
   - 刷新页面应该能解决

## 数据备份

### 导出数据（强烈推荐）

在控制台运行：
```javascript
await dbDebug.exportData()
```

这会下载一个JSON文件，包含所有数据。

### 手动备份

1. 打开开发者工具 → Application → IndexedDB
2. 右键点击 `CocktailMenuDB`
3. 选择导出选项（如果浏览器支持）

## 技术说明

### 为什么会出现这个问题？

我们添加了 `displayOrder` 字段来支持排序功能。升级过程中：

1. **Version 3** 添加了新的索引
2. 升级脚本应该自动为现有数据添加 `displayOrder` 值
3. 但查询语句改为使用 `orderBy('displayOrder')`，如果字段缺失可能导致查询失败

### 已修复的问题

1. **查询逻辑优化**
   ```typescript
   // 旧代码（可能失败）
   db.recipes.orderBy('displayOrder').toArray()
   
   // 新代码（兼容性更好）
   const allRecipes = await db.recipes.toArray();
   return allRecipes.sort((a, b) => {
     const orderA = a.displayOrder ?? a.id ?? 0;
     const orderB = b.displayOrder ?? b.id ?? 0;
     return orderA - orderB;
   });
   ```

2. **升级脚本改进**
   - 添加了详细的日志输出
   - 使用更安全的更新方式
   - 确保每条数据都被处理

## 调试工具使用说明

### 可用命令

在浏览器控制台中，您可以使用以下命令：

#### 1. 检查数据库状态
```javascript
await dbDebug.checkStatus()
```
**输出示例**：
```
=== 数据库状态检查 ===
配方数量: 10
原料数量: 25
菜单信息数量: 10
店面数量: 2
缺少displayOrder的配方: 0
缺少displayOrder的原料: 0
```

#### 2. 修复displayOrder字段
```javascript
await dbDebug.fixDisplayOrder()
```
**输出示例**：
```
=== 开始修复displayOrder字段 ===
修复了 10 个配方的displayOrder
修复了 25 个原料的displayOrder
=== 修复完成 ===
```

#### 3. 导出所有数据
```javascript
await dbDebug.exportData()
```
**效果**：下载一个包含所有数据的JSON文件

## 如果数据真的丢失了

### 检查是否在不同浏览器

IndexedDB数据是按浏览器存储的：
- Chrome的数据在Chrome中
- Firefox的数据在Firefox中
- 不同浏览器的数据互不相通

### 检查浏览器配置文件

如果使用了多个Chrome配置文件，数据可能在另一个配置文件中。

### 恢复选项

1. **从备份恢复**（如果之前导出过）
2. **从浏览器历史恢复**（某些浏览器支持）
3. **重新输入数据**（最后的选择）

### 定期备份


如果您是开发者，可以：

2. 定期提交数据快照

### 浏览器同步

考虑使用：
- Chrome的配置文件同步
- 或实现云端备份功能
